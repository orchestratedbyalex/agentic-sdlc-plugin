# Agent evals

Evals for the plugin's **own agents**: golden target-repo fixtures with labelled
outcomes, driven headless through the real plugin (`claude -p --plugin-dir .`), asserted
mechanically on each gate report's machine-parsable `VERDICT: PASS|FAIL` line — never an
LLM judging an LLM. A "live run worked once" is a demo; these are the repeatable check
that a gate agent still catches what it exists to catch.

> **Billed.** Every case spawns a real `claude` session (your account, your configured
> default model unless `--model` says otherwise). That is why evals are opt-in behind
> `SDLC_EVALS=1` and are **never** part of `node --test` — CI and contributor machines
> stay model-free.

## Run

```bash
node evals/run.mjs --list                         # list cases (free)
SDLC_EVALS=1 node evals/run.mjs                   # run every case on your default model
SDLC_EVALS=1 node evals/run.mjs --case <id>       # one case (repeatable / comma-separated)
SDLC_EVALS=1 node evals/run.mjs --model <model>   # route to a specific model
SDLC_EVALS=1 node evals/run.mjs --keep            # keep the fixture workdirs for inspection
```

Each run writes `evals/results/<stamp>/<case>/` (gitignored): the full stream-json
`transcript.ndjson`, the extracted subagent `report.md`, and `meta.json`
(verdict, failures, cost, duration). Exit code 0 = every case matched its label.

## How a case runs

1. The fixture is copied to a throwaway temp dir and given a deterministic baseline
   commit (fixtures carry no `.git`; a fixture's `_eval-uncommitted/` overlay, if any,
   is applied *after* the commit — that is how diff-reviewing agents get an
   uncommitted "change under review").
2. `claude -p` starts **inside the workdir** with `--plugin-dir` pointing at this repo,
   and is instructed to dispatch exactly one subagent
   (`agentic-sdlc:<agent>`) via the Agent tool.
3. The subagent's final message is extracted from the stream — from the Agent
   tool_result, or from its completion `task_notification` when the CLI ran the
   dispatch in the background; the top-level model's relay is only a last-resort
   fallback (`reportSource` in `meta.json` says which path was used).
4. `evaluateCase` asserts the labelled `VERDICT:` plus any `mustMatch`/`mustNotMatch`
   patterns (e.g. the verbatim Execution Evidence contract).

## Fixture rules (enforced by a structure test)

- Under `evals/`, **no** file may match `node --test` discovery — no `*.test.mjs`/
  `*-test.mjs`/`test.mjs` names and no directory named `test/` — because the root
  test runner executes every match, fixtures included. Fixture suites live in
  `spec/*.check.mjs`, invoked by explicit path from the fixture's `package.json`.
- Every fixture is a complete miniature target repo: `CLAUDE.md` (the commands the
  agent will trust), `package.json`, and `docs/requirements/sdlc-metadata.yml`
  generated by the state script (phases 1–4 completed, so the project resumes at
  Verify).
- Fixtures must stay dependency-free (`npm install` never runs).
